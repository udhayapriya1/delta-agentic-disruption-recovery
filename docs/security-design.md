# Architecture and security review

The verified system handles only synthetic records. The security boundary is independently enforced in API code and Salesforce permissions; model instructions are not authorization.

Implemented: signed JWT issuer/audience/expiry and role validation; subject-to-PNR checks; consent checks; fixed API routes; Pydantic allowlists; parameterized Snowflake queries; custom Apex permission; encrypted Salesforce external credential; P001-only expiring demo principal; explicit short-lived selection acceptance; payload-bound idempotency; atomic inventory/booking transaction; separate approver role and self-approval denial; masked audit; rate limiting; guarded same-cabin/window policies; no card-refund route; safe 409/503/504 handling. Local tests cover these boundaries, and actual Agentforce runs cover selected positive, above-cap, injection, timeout and inventory-race cases.

Critical production gates: replace CLI-backed Salesforce REST with dedicated OAuth; use approved persistent HTTPS hosting and secret management; bind real channel identity per customer/session; distribute rate limiting and durable work queues; operate the existing durable handoff retry worker; verify staffed routing and acknowledgement; enforce source retention/classification/deletion; expand native identity evaluation coverage before broadening the fixed P001 pilot; expand native federation coverage and platform evaluation cases. The existing demo is not approved for real passengers.

Cloudflare terminates the temporary HTTPS tunnel and is an explicit trust processor. User authorization covered only an expiring P001 token and exclusively synthetic context, and renewal was separately approved. No tokens or passwords are stored in source, public evidence or Git. `tmp/cloud-runtime.json`, local databases and downloaded tools are ignored. The tunnel and runtime service are temporary and must be stopped after use; API credentials expire even if the process remains running.

The actual platform evaluation reports include failures. Do not interpret all local tests passing or a successful live scenario as universal policy compliance. Earlier prompt-injection false positives, topic naming/cache mismatches and ambiguous outcome wording were diagnosed and corrected. The final selected four native cases passed twelve assertions; this remains a small evaluation sample. No production penetration test, compliance certification, cross-region protection or surge SLA is claimed.
